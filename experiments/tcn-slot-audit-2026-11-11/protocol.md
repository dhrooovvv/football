2. **static**: for each real half, independently choose one fixed permutation within each team's player slots and apply it to entire8channel object vectors, including stored velocity. Ball vector and core9 unchanged. This is the pure fixed-order invariance control; no velocity rederivation. Report probability max difference, allclose(atol1e-6,rtol1e-5), CSV disagreement frames and quality. Summation rounding can affect bytes; no claim of exact bitwise permutation invariance.
3. **rederived_identity**: keep original ordering but recompute only player velocity from encodedXY. vel=clip(12.5*diff(encodedXY),-5,5) when adjacent current/prior shuffled-slot observations are both visible; zero otherwise and at each real half's first frame. 4. **dynamic**: independently permute within each team's slots at every frame, then rederive player velocity with the same rule. Positions/visibility per team remain the same multiset each frame; ball8, core9, team-role membership, labels, ball gaps and half boundaries preserved. This jointly stresses false adjacent-slot velocities and pre-pooling object histories; it does not isolate their individual effects.

Only rederive velocity within half blocks; never cross halftime or true-label gaps. No additional missingness, interpolation, duplicates, guessed person identities or target-derived settings.
