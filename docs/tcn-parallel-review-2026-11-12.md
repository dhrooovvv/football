## Hypotheses and decisions

The attention hypothesis is that a masked relational aggregation module can retain useful possession evidence that uniform per-team means dilute, improving whole-spell quality. The experiment replaces one pooling module while preserving the retained temporal motion encoder, data, schedule, decoder and evaluation. Adding attention parameters changes capacity and optimization as well as weighting; any gain supports the complete fixed replacement, not a causal claim that attention weighting alone caused it. It is a project adaptation of a paper mechanism, not a faithful reproduction or an expected gain.

The ensemble hypothesis is that a second independently initialized instance of the retained original TCN makes complementary errors. Equal probability averaging may improve detection and timing. The fixed second initialization seed changes neither sampler nor gap-view seeds, so this specifically tests initialization diversity; it does not characterize all sources of random training variance. Exact repeated fits at the same initialization establish repeatability and add no ensemble diversity.

Both arms screen independently against the same frozen, fold-safe staged40k parent. This permits concurrent computation without allowing one unfinished arm to redefine another arm's parent. Finalization must follow a preregistered decision order: attention first against the frozen parent, then the original-model seed ensemble against the retained best after that decision. An attention pass does not automatically justify combining attention with the seed ensemble. If both fail, retain the original parent. Means alone cannot override the gate.

The gate remains positive median paired clean/corrupted spellF1 change, at least3/5 paired wins, paired median macroF1 change no lower than-.01, median corrupted spellF1 change at least+.01, and required contract/repeatability evidence. Every arm, fold, condition and rejection must be recorded. The user has authorized one attention trial and one fixed seed-ensemble trial, not seed selection, blend-weight search, architecture variants or a general reopening of stopped tracks. Preserve prior failure histories.

## Preconditions and uncertainty

- Each held-out development match must be excluded from every corresponding fit, including preprocessing. Existing all-five final artifacts are ineligible evaluation parents. Both sealed IDSSE matches, PFF holdouts, other providers and all target data remain excluded.
- The frozen parent's checkpoint identity, original registration, loss/sampling evidence, CSV bytes and scores must be reconstructed before comparing new predictions. A method mismatch cannot be treated as an experimental result.
- Attention masks must exclude unseen/padded keys and queries, preserve finite zero outputs for an entirely unobserved team, and leave the ball pool and temporal model unchanged. Shared original layers must initialize identically to the parent before new attention layers consume RNG.
- Both stages must preserve the40k budget and halfway Adam/window-view-RNG reset. Checkpoint resumption must restore all necessary random and optimizer state. Repeated fits and both-view reload/batch CSV checks provide computational evidence, not quality evidence.
- Five development matches have been reused many times and LOMO training sets overlap. The prescribed gate is an engineering decision rule; it is not an independent confirmatory test. Correlated frames and overlapping folds do not support a naive population confidence interval or p-value. The once-only sealed evaluation remains November16, with weak results triggering investigation rather than tuning.
- Report per-match clean/corrupted results, short-spell recall, missed/spurious spells, boundary errors and precision/recall/F1 at each official IoU threshold. A mean improvement can hide match or duration regressions, and increased precision from smoothing can erase short possessions. None of these diagnostics substitutes for the official gate.

## Concurrent execution contract

One thread per independent training process means two concurrent jobs nominally occupy two CPU execution threads. It does not mean one total core or twice the throughput. Both processes share RAM, memory bandwidth, storage and thermal limits. Read-only memory maps may share file-backed pages, while labels, batch arrays, activations, gradients and attention intermediates are separate allocations. Exact peak RAM and runtime require user measurement; no hard cap or guaranteed speedup is justified by source inspection.

Use arm-specific locks, checkpoint directories, test logs, private CSV directories, results and failure records. Each arm runs its own folds sequentially; two arms do not authorize twenty simultaneous fits. Interrupted work must retain evidence and resume only identical registrations. Finalization starts only after both completed arm results pass integrity checks and must not race with a running arm.
