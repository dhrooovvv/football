## Fixed architecture and estimand

Reuse the existing521-column tensors and all precomputed clean/augmented/evaluation views. The candidate reads ONLY centeredXY and visibility channels[0,1,4] from each object, applies a shared pointwise3→8 linear embedding plusReLU, takes visibility-masked means forH/A/ball, concatenates the unchanged nine core features, and runs the original33→32→32→32→3 temporal stack at dilations1/2/4 with kernel3 and pointwise output. No per-slot temporal convolution occurs before pooling and stored object velocity channels2/3 are ignored for ALLobjects.

This changes both motion-feature access and the object encoder's temporal kernel as one semantic representation redesign. It does not isolate which component causes any score difference. The candidate has9,539parameters versus9,635, and its encoded receptive field is15frames/radius7 versus17/radius8. No extra layer, context, width or capacity compensation should be added. Keep250input/25halo/200lossframes; extra halo remains adequate for both architectures.

The learned ball embedding also loses velocity-vector access and local pre-pooling ball history, while the unchanged core still supplies instantaneous ball-speed magnitude and gap age. Thus this is not a motion-free model: collective dynamics can be learned after pooling, and scalar ball motion remains. Losing individual relative paths or ball-motion direction can hurt, especially brief team-control transitions. Those trade-offs must be disclosed rather than interpreting any result as a pure win from less capacity.

## Why identity dependence is removed, and what remains

For a given frame, any permutation of player object vectors WITH their role/visibility flags leaves each team's mathematical masked mean unchanged. Since the embedding has no time axis and stored slot velocity is ignored, the permutation may differ at every frame without changing the pooled mathematical sequence. The later temporal convolution sees the same collective sequence. Floating reduction order can perturb finite-precision probabilities, so tolerance-based synthetic invariance tests are appropriate; byte identity is still required for repeated execution of the same input/mode.

The nine existing core features are nearest per-team distances/margin, observed-ball speed, pitch edge, observation masks and gap age. They do not use player PersonId or same-slot player velocity. Ball motion assumes the unique ball track, not player identity. Source-level reasoning supports removing the specific player-identity assumption, not proof of target robustness. Missing/duplicated observations can alter means, team errors alter pooling, source label conventions persist, and no compatible input representation can recover absent information automatically.
