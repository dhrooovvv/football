# Hybrid architecture decision from primary evidence

Researched November 14, 2026. Question: which single hybrid most directly addresses the measured possession errors while reusing the completed TCN? Scope is the existing five IDSSE development matches, original LOMO splits, fixed seeds, revised gate and November 16 freeze. No tests, code imports, training, inference, checkpoint/array loading, datasets or source repositories were downloaded. Only this assigned research file was written. The parent owns journals, source registration and final decisions.

## Decision

Recommend **one frozen TCN plus temporal probability-refinement candidate** before a new GNN–TCN encoder. Confidence is moderate in the choice of mechanism and low in any gain prediction. The direct project evidence is stronger than architectural popularity: long-gap absence of an argmax spell match leads on all five matches, and 289 of 359 clean-matched spells lost under corruption intersect bursts over ten seconds. Current local context is about .68 seconds.

The earlier 13-second TCN failure remains contrary evidence. It trained a deeper network from scratch and selected a CatBoost blend. A frozen local predictor with a separate residual probability-refinement stage changes the learning problem and preserves already learned local distinctions. This difference makes a new bounded hypothesis defensible but supplies no expected score gain. Source evidence is the saved reviews under experiments/tcn-context-2026-11-11 and experiments/tcn-diagnostic-2026-11-13.

## Concrete implication for the proposed candidate

Use the frozen B out-of-fold ensemble probabilities, a compact coarse-rate temporal refiner and a residual correction to full-rate log probabilities. Retain decoder16 and full-rate local predictions. Start from zero correction. The first candidate should use probability inputs alone. The existing proposal's nine extra core inputs should not enter automatically: they would increase the mechanism changes, while the published refinement ablation provides contrary evidence to indiscriminate feature concatenation. That ablation concerns hidden features rather than our core channels, so it does not prove core channels harmful. It supports choosing the smaller prospective test.

A roughly 25-second coarse context is a project adaptation intended to span measured bursts. No paper establishes that length as optimal. Do not search context, blend weight, decoder or smoothing alongside the new stage. Freeze the sampling, labels, loss and other evaluation choices relative to the retained parent where technically applicable. Report long-gap recovery and short-spell recall along with the unchanged full gate.

Frozen-parent probabilities on their own training matches create a stacking distribution shift. Any implemented protocol must state whether training inputs are in-sample or generated through nested held-out parent fits. Nested fits add substantial work. Held-out evaluation folds must never enter parent training, refiner training, preprocessing or unlabelled pretraining. Existing final-all-five models cannot be used for development evaluation.

## GNN–TCN assessment

A graph encoder can explicitly represent player–ball, opponent and teammate relations that the current masked mean pool compresses. The failed attention model only attended within each team and is not a complete test of cross-team edge geometry. Conversely, that failure supplies no positive evidence that a graph will help. Adding graph messages and a longer temporal model together prevents attribution. A GNN–TCN remains a later hypothesis if observed-ball wrong-team errors dominate after temporal work, rather than the first response to the present diagnostic.

Spatial GNNs do not automatically gain longer temporal support or identity continuity. Persistent player paths and velocity features still require appropriate slot consistency and visibility masking. A graph output is only invariant after an appropriate graph-level readout, while node outputs are ordinarily equivariant. Current shared-object processing and masked team means already provide static within-team permutation invariance up to floating-point reduction effects.

## MacBook feasibility and uncertainties

A small probability-only refiner is the lowest engineering and activation-memory option among these candidates. This is a structural estimate: it processes three coarse-rate channels rather than all player pairs and long per-player sequences. Existing CPU PyTorch can express it without a new graph library. Its exact parameter count, process RSS, runtime, repeatability and fresh-environment reproduction remain unmeasured and need user-run checks. No hour/minute forecast is established.

GNN–TCN training could be made small enough for an 18GB M3 MacBook, but parameter size alone cannot certify fit. Pairwise edge activations, temporal windows, two simultaneous workers and whole-match preparation affect peak memory. Neither full TranSPORTmer nor PathCRF has been hardware-qualified here. Their reported GPU timings cannot be converted into our CPU runtime.

The recommendation could change if a fold-safe diagnostic shows long-gap errors arise chiefly from lost relational information rather than temporal insufficiency, or if the refiner cannot recover spells without erasing short ones. Existing counts are associations. The immediate evidence step is a fixed user-run correctness/resource preflight followed by exactly one registered full comparison if feasible before the freeze. No broader model search is recommended.

Parent decision discussion fixes probabilities plus the existing observation-mask and gap-age controls as a possible compromise, supplying missingness information absent from probabilities alone. This differs from this researcher's probability-only preference. The paper's hidden-feature concatenation ablation does not test those two controls and cannot settle that choice. The final decision memo/protocol should state the chosen interface explicitly and avoid adding hidden embeddings, nine core features and graph messages together.
